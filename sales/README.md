# نظام مبيعات ROCK

واجهة داخلية عربية RTL لإدارة فريق المبيعات، تعمل على المسار /sales/ داخل نسخة ROCK المستضافة على خادم PHP.

## الوحدات

- دخول موحّد باستخدام حساب مدير ROCK الحالي أو حساب مندوب أنشأه المدير.
- لوحة متابعة للمبيعات والعملاء والعروض والطلبات.
- ملفات العملاء، مع توزيع العملاء على المندوبين وسجل المكالمات والزيارات والملاحظات.
- عروض أسعار مرتبطة بمنتجات الكتالوج وأسعار قاعدة البيانات وقت إنشاء العرض.
- تحويل العرض إلى طلب من خلال اعتماد الإدارة.
- متابعة حالة الطلب: معتمد، قيد التجهيز، مشحون، تم التسليم، ملغي.
- تسجيل دفعات جزئية أو كاملة مع مرجع وطريقة التحصيل.
- إدارة حسابات المندوبين وإيقافها وإعادة ضبط كلمات المرور.
- إدارة المخزون الاختيارية؛ يُخصم الرصيد عند تحويل حالة الطلب إلى "تم الشحن"، ويُمنع الشحن عندما لا يكفي الرصيد المتتبّع.
- تقارير أداء المندوبين وتصدير الطلبات بصيغة CSV.
- العمولات بالنسب المئوية: نسبة عامة مع تخصيص لكل مندوب. لا تظهر إعدادات العمولة أو قيمتها أو تقاريرها في جلسة المندوب. تثبت النسبة ومبلغ العمولة عند اكتمال تحصيل الطلب، وتُحسب على صافي الطلب بعد الخصم.

## متطلبات التشغيل

**GitHub Pages لا يشغّل PHP.** لذلك لا يكفي نشر مجلد sales/ على GitHub Pages لعمل تسجيل الدخول وحفظ البيانات. يجب رفع نسخة الموقع المبنية إلى استضافة تدعم PHP 8.1+ وMySQL، مثل إعداد Hostinger القائم في مشروع ROCK.

المتطلبات:
- PHP 8.1 أو أحدث.
- إضافات pdo_mysql وmbstring.
- قاعدة MySQL موجودة ومُعدّة لملفات ROCK الحالية.
- HTTPS مفعّل.

## التثبيت على الاستضافة

1. استخدم دليل المشروع الأساسي HOSTINGER-ADMIN-SETUP.md لإعداد قاعدة بيانات ROCK وملف api/config.php وإنشاء أول حساب مدير من /api/install.php.
2. بعد نجاح تهيئة المتجر، احذف api/install.php من الاستضافة وفق تعليمات الدليل.
3. انشر مجلد sales/ كاملًا مع ملفات ROCK في نفس جذر الموقع؛ يجب أن يكون المسار النهائي مثل https://YOUR-DOMAIN/sales/.
4. افتح /sales/ وسجّل الدخول بحساب المدير نفسه الذي تم إنشاؤه للوحة الإدارة الحالية.
5. من قسم "إدارة المندوبين"، أنشئ حسابًا لكل مندوب وحدد كلمة مرور أولية لا تقل عن 12 حرفًا. يمكن ترك نسبة العمولة فارغة لتطبيق النسبة العامة.
6. اضبط النسبة العامة من قسم "العمولات". تبدأ القيمة الافتراضية بصفر حتى يحدد المدير المعدل المعتمد.
7. فعّل تتبع المخزون لكل منتج بعد إدخال رصيد حقيقي. المنتجات غير المتتبعة لا يُمنع شحنها بسبب عدم وجود رصيد.
8. اختبر بحساب تجريبي: عميل، عرض سعر، اعتماد طلب، تسجيل دفعة، ثم تحقق من ثبات العمولة في لوحة الإدارة فقط.

## الصلاحيات والبيانات

- الإدارة تستطيع رؤية جميع العملاء والمستندات والمندوبين والمخزون والعمولات والتقارير.
- المندوب يرى العملاء والمستندات المرتبطة بحسابه فقط، ويمكنه إنشاء عملاء وعروض أسعار ومتابعة سجلاته.
- لا تُرسل نسب العمولات أو قيمها إلى API للمندوب، وتُفحص الصلاحيات على الخادم في كل طلب.
- كلمات المرور تُخزّن باستخدام password_hash، وتُتحقق باستخدام password_verify.
- جميع عمليات POST تتطلب رمز CSRF وجلسة same-origin.
- تُستخدم أسعار المنتجات المحفوظة في قاعدة ROCK؛ لا يقبل الخادم سعر الوحدة من المتصفح.
- لا يُسجّل النظام دفعات أكبر من الرصيد المتبقي، ولا يكرر خصم المخزون عند تغيير الحالة لاحقًا.

## حدود النسخة الحالية

- لا يوجد دفع إلكتروني أو تكامل بنكي؛ تسجيل التحصيل يدوي من الإدارة.
- لا يوجد إرسال بريد أو واتساب آلي؛ يسجل المندوب النشاط ويستخدم وسائل التواصل الخارجية.
- لا يوجد استيراد تلقائي لمخزون المستودع؛ إدخال الرصيد وتحديثه مسؤولية الإدارة.
- لا تُفعّل العمولات بأثر رجعي عند تغيير النسبة. تُحفظ النسبة التي كانت فعّالة لحظة اكتمال التحصيل.
- بيانات نسخة GitHub Pages العامة تظل منفصلة عن قاعدة PHP/MySQL؛ بيانات المبيعات لا تُخزّن في localStorage أو في ملفات JavaScript العامة.

## الفحوصات

يشمل سير GitHub Actions فحص صياغة PHP، وفحص JavaScript، واختبارًا ساكنًا لوجود حدود الصلاحيات والميزات الحرجة. يلزم اختبار تشغيل متكامل بعد إعداد قاعدة البيانات على الاستضافة.
